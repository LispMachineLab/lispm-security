#+title: LispM Security

#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-security/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-security/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

Security checks what the agents of an Emacs are given to run: the MCP servers and skills of
[[https://github.com/LispMachineLab/lispm-agent][LispM Agent]], Claude Code and Codex, and Emacs's own packages.  It is an application of
[[https://github.com/LispMachineLab/lispm-desktop][LispM Desktop]], which its App Store installs, and works in any Emacs 30.1 or later.  In code, the
prefix is ~lispm-security-~.

* What it checks

A scan reads and never runs anything: no server is started, no skill's code evaluated, nothing
sent over the network.  For each agent, it finds the servers and skills the agent itself would
find, then checks them:

- *Servers.*  A package npx or uvx runs without an exact version, so that each start may run
  another; a container image named by a tag; a command line given to a shell; a remote server
  over plain HTTP; a secret written out in the configuration file; packages that run scripts
  when installed.  The versions servers do run, and what they bring along, are read from npx's
  and uv's caches.
- *Text models read*, skills' instructions and tools' descriptions: characters a reader does
  not see, Unicode tags spelling out hidden text, comments Markdown hides, blank lines pushing
  the rest out of view, encoded payloads, downloads piped into a shell, addresses that collect
  data, words telling the model to drop its instructions or keep something from the user, files
  of credentials.
- *The code of LispM's skills*, read as Lisp: what it runs, reaches and changes; whether it
  changes what decides what agents may do (LispM's policy, the skills trusted, Emacs's guards),
  changes other functions, such as ~y-or-n-p~, or computes which function it calls; and whether
  each of its tools is of the permission class what it does needs.  A tool of class read runs
  without asking, so one that runs programs must say so.
- *Tool pinning.*  Once the user trusts a running MCP server's tools, they are pinned by their
  hash; a server whose tools then change, a rug pull, is reported with what changed.
- *Known vulnerabilities and malicious packages*, looked up in [[https://osv.dev][OSV]], which gathers GitHub's,
  PyPI's, Go's and RustSec's advisories and OpenSSF's malicious packages.  Looking up tells
  osv.dev the names and versions of the packages, so it happens only when the user asks, and
  after they agreed (~lispm-security-look-up~); scans use what was looked up last.
- *What agents may do unasked*: LispM's default policy, Claude Code's mode that bypasses
  permissions, Codex without its sandbox.

Rules flag what deserves a look.  The user judges: a finding they find harmless they set aside,
and it stays so.

* Using it

=M-x lispm-security= opens its window, the findings the worst first.

| =RET= | what the finding means, where, and what to do                  |
| =g=   | scan again                                                     |
| =l=   | look the packages servers run up in OSV                        |
| =t=   | trust the tools of the finding's MCP server: pin them as they are |
| =x=   | set the finding aside, or take it back                         |
| =o=   | visit the file the finding is about, at its line               |
| =i=   | the inventory: what each agent is given                        |
| =a=   | show the findings set aside too                                |

Agents read the findings with the Security skill of the [[https://github.com/LispMachineLab/lispm-store][LispM Store]]; what was found is quoted
to them as data.  They can neither trust a server nor set a finding aside: only the user can, in
the window.

What Security keeps, pins, findings set aside and what OSV answered, is in
=~/.emacs.d/lispm-security/= (~lispm-security-directory~).

* Installation

From LispM Desktop's App Store: Utilities, Security, Get.

By hand, from a checkout:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/src/lispm-security")
(require 'lispm-security)
#+end_src

* Tests

#+begin_src sh
make test compile
#+end_src

They make up every file they read and send nothing.  With checkouts of lispm-agent, lispm-desktop
and lispm-browser beside this one (or ~LISPM_AGENT=~, ~LISPM_DESKTOP=~ and ~LISPM_BROWSER=~ naming
their lisp/), the tests of how Security works with them run too.
