#+title: LispM Security

#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-security/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-security/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

Checks what the agents in your Emacs are given to run: the MCP servers and skills of
[[https://github.com/LispMachineLab/lispm-agent][LispM Agent]], Claude Code and Codex, and Emacs's own packages.  It is an application of
[[https://github.com/LispMachineLab/lispm-desktop][LispM Desktop]]'s App Store, and works in any Emacs 30.1 or later.  In code, the prefix is
~lispm-security-~.

* What a scan checks

A scan only reads: it starts no server, evaluates no skill and sends nothing over the network.
For each agent it finds the servers and skills that agent would, and flags:

- *Servers*: npx or uvx packages without an exact version, container images named by a tag,
  command lines given to a shell, remote servers over plain HTTP, secrets in configuration
  files, packages with install scripts.  Versions actually run are read from npx's and uv's caches.
- *Text models read* (skill instructions, tool descriptions): invisible characters, hidden
  Unicode tags and Markdown comments, encoded payloads, downloads piped into a shell, data
  collecting addresses, prompt injection, credential files.
- *LispM skills' code*, read as Lisp: what it runs, reaches and changes; whether it touches the
  policy, trusted skills or Emacs's guards, advises functions such as ~y-or-n-p~, or calls
  computed functions; whether each tool's permission class fits what it does.
- *Tool pinning*: trusted MCP tools are pinned by hash, so a server whose tools later change (a
  rug pull) is reported with the change.
- *Known vulnerabilities and malicious packages*, from [[https://osv.dev][OSV]].  Looking up sends package
  names and versions to osv.dev, so it happens only when you ask (~lispm-security-look-up~).
- *What agents may do unasked*: LispM's default policy, Claude Code's bypass-permissions mode,
  Codex without its sandbox.

Findings you judge harmless can be set aside, and stay so.

* While agents work

With LispM Agent 0.3.0 or later, Security also checks each tool call of LispM's agents before it
runs, and each MCP server's tools before agents see them:

- *Untrusted servers*: every call of their tools asks, until you trust the server (=t=).
- *Tools changed since you trusted them*: hidden from agents and their calls denied
  (~lispm-security-changed-tools~ ~ask~ makes them ask instead).
- *Toxic flows*: once a session has read untrusted content (the web, MCP results) and private
  data (your files, its memory), a call that can send data out asks
  (~lispm-security-toxic-flows~).

A failing check counts as one that asks, and Security can only tighten LispM's decision, never
loosen it.  ~lispm-security-guard~ turns it all off, which a scan then reports.

* Using it

=M-x lispm-security= opens the findings, the worst first.

| =RET= | what the finding means, where, and what to do         |
| =g=   | scan again                                            |
| =l=   | look up the packages servers run in OSV               |
| =t=   | trust the finding's MCP server: pin its tools as they are |
| =x=   | set the finding aside, or take it back                |
| =o=   | visit the file the finding is about                   |
| =i=   | the inventory: what each agent is given               |
| =a=   | show the findings set aside too                       |

Agents can read findings through the Security skill of [[https://github.com/LispMachineLab/lispm-store][LispM Store]], but only you can trust a
server or set a finding aside.  Pins, findings set aside and OSV answers are kept in
~lispm-security-directory~ (=~/.emacs.d/lispm-security/=).

* Installation

From LispM Desktop's App Store: Utilities, Security, Get.  By hand, from a checkout:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/src/lispm-security")
(require 'lispm-security)
#+end_src

* Development

=make test compile= runs the tests, which make up every file they read and send nothing.  With
a checkout of lispm-agent beside this one (or ~LISPM_AGENT~ naming its =lisp/=), the integration
tests run too.  A test checks that no file of Security but the tests names LispM Desktop's code:
the desktop dresses Security's window from its own side, with ~lispm-security-status~,
~-trust-enabled-p~, ~-inventory-p~, ~-shown~ and ~-visitable-p~.
